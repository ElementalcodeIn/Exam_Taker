1. Which tool in the classic dsniff suite is specifically aimed at forcibly terminating existing TCP connections (useful in labs to disrupt a legitimate endpoint and attempt takeover) by sending forged packets to the endpoints?
A. tcpkill
B. arpspoof
C. urlsnarf
D. webmitm
Correct Answer: A Explanation: tcpkill (part of the dsniff toolkit) actively injects forged TCP packets (e.g., RSTs) to kill or disrupt established TCP connections based on host/port filters — a technique sometimes used in controlled lab settings to desynchronize or interrupt flows prior to attempting takeover. arpspoof (B) performs ARP poisoning to perform MITM redirection on local LANs but does not itself inject RSTs to kill sessions. urlsnarf (C) passively logs HTTP requests/URLs from captured traffic (useful for reconnaissance) but does not disrupt sessions. webmitm (D) is not a standard dsniff tool name here (there are web-facing MITM utilities but not a canonical “webmitm” in dsniff); it’s not the specific tcp-termination tool. In controlled testing, tcpkill is the explicit utility for killing sessions.

2. Your target uses OAuth 2.0/OIDC for “Sign in with Provider.” During testing, you find the authorization server accepts multiple callback endpoints and the relying party (RP) allows arbitrary subpaths. Which parameter MUST be strictly allowlisted (exact match or with well-scoped patterns) to prevent authorization code leakage via open redirects?
A. redirect_uri
B. state
C. scope
D. response_type
Correct Answer: A Explanation: The redirect_uri determines where the authorization server sends the authorization code or tokens; if it’s not strictly allowlisted, an attacker can pivot through open redirectors to capture codes/tokens (A). The state (B) mitigates CSRF and session mix-ups but does not stop code delivery to a hostile URI if the redirect URI itself is not constrained. scope (C) limits token permissions, not where they are sent. response_type (D) dictates code vs token delivery but again doesn’t restrict destinations. Best practice is exact-match redirect_uri registration, pairing with state and PKCE, and rejecting wildcards/unregistered hosts.

3. While analyzing a raw email header to trace the true sending path, which field provides the MOST reliable origin detail for footprinting when evaluated correctly?
A. Return-Path
B. From:
C. The earliest (bottom-most) Received: header added by the first MTA
D. Reply-To:
Correct Answer: C Explanation: The most defensible way to reconstruct the sending path is to parse the Received: chain chronologically; the earliest (bottom-most) Received: header is added by the first Mail Transfer Agent (MTA) that handled the message and typically includes the originating client/MTA hostname and connecting IP—crucial for source attribution during email footprinting. A) Return-Path is set by the final MTA and often reflects the bounce address, which can be spoofed or rewritten. B) From: is a display identity, trivially spoofable and not transport-authenticated. D) Reply-To: is user-controlled and useful for social-engineering detection but not reliable for transport path reconstruction. Robust methodology correlates the earliest Received: with Authentication-Results (SPF/DKIM/DMARC) to strengthen confidence.

4. During a supply-chain review, you find a CI system (e.g., GitHub Actions/GitLab CI) stores static cloud API keys as repository secrets used by pipelines. A compromise of the CI runner allowed an attacker to exfiltrate these keys and pivot into the cloud account. What is the BEST architectural remediation?
A. Encrypt the static keys with KMS and decrypt them at job start
B. Restrict CI runners by IP allowlist to call the cloud provider APIs
C. Replace static keys with OIDC/workload identity federation from CI to the cloud; issue short-lived, scoped tokens with least-privilege
D. Require developers to manually rotate the keys after each deployment
Correct Answer: C Explanation: C is correct because OpenID Connect/workload identity federation eliminates static secrets in CI by exchanging signed identities for short-lived tokens scoped by IAM conditions/permissions boundaries; even if the runner is compromised, token lifetime/scope limit blast radius; A keeps long-lived keys (encryption at rest ≠ removal of secret); B reduces where calls originate but doesn’t stop key theft or misuse; D improves hygiene but leaves the fundamental static-secret risk. CEH-aligned practices: least-privilege roles, signed provenance (SLSA), admission verification, and secret-zero elimination patterns.

5. While enumerating asset storage, you identify media.target.com as a CNAME to media-target-public.s3.amazonaws.com. You must verify exposure without exceeding scope or altering data. What is the BEST next step?

6. Which active network probe is a defensible technique to detect centralized sniffers that rely on port mirroring (SPAN) but may not be present on every access switch?
A. Send crafted multicast frames with unlikely multicast addresses and monitor whether they are observed on the mirrored analysis host (if you control it)
B. Flood the network with DHCPDISCOVER packets to stress the DHCP server
C. Continuously ping all hosts to force ARP requests and reveal sniffers
D. Run a continuous traceroute to every internal host
Correct Answer: A Explanation: A is correct because sending crafted multicast (or unicast-to-nonexistent) frames that normally would not traverse to the analyzer unless mirrored, and then checking whether those frames appear on the mirrored collector, can reveal whether port mirroring is configured to include certain ports or VLANs—this is a focused, minimally disruptive probe to detect SPAN-based sniffers. Option B (DHCPDISCOVER flood) is an attack-like behavior and disruptive. Option C (continuous ping) generates normal traffic but won’t reliably expose SPAN collectors; it can create noise and false positives. Option D (traceroute) tests routing paths, not L2 mirroring. Carefully scoped active probes like (A) are standard in defensive audits to discover unauthorized mirroring.

A tester demonstrates “login CSRF” to bind a victim’s browser to the attacker’s account, after which the attacker piggybacks the victim’s actions. Which fix most directly addresses this risk?

Correct Answer: C Explanation: The state parameter (and PKCE where applicable) provides request integrity linking the authorization response to the initiating client context, preventing login CSRF and session swapping; robust validation of state is the primary, standards-aligned mitigation. 10. A customer prohibits any queries to their infrastructure, including DNS lookups to their authoritative servers. You still need to enumerate historical and current subdomains to understand the organization’s external footprint. Which method is MOST appropriate?

Correct Answer: D Explanation: Passive DNS repositories aggregate historical DNS observations from third-party sensors and resolvers, enabling subdomain and infrastructure discovery without contacting the target’s nameservers, consistent with strictly passive reconnaissance and MITRE T1596/T1590. B. Unauthorized actions performed by the receiving application, leading to privilege escalation

12. Which persistence mechanism is MOST stealthy from a host-based forensic perspective because it stores payloads in places not listed by normal directory listings and is often overlooked?
A. Dropping a binary in %TEMP% and hiding the file attribute.
B. Storing a payload inside an NTFS Alternate Data Stream (ADS) attached to an innocuous file.
C. Creating a hidden service with an innocuous display name.
D. Installing a scheduled task that runs a PowerShell script from %APPDATA%.
Correct Answer: B Explanation: Option B is correct because NTFS Alternate Data Streams attach named streams to an existing file’s primary data stream and do not appear as separate files in normal dir/Explorer listings; ADS can be used to conceal small executables, configuration blobs, or scripts in otherwise benign files and are commonly overlooked in cursory examinations unless stream enumeration tools are used. Option A (file in %TEMP% with hidden attribute) is visible via dir /a and many EDRs/forensics tools monitor %TEMP% for suspicious executables; it is not as covert as ADS. Option C (hidden service) still creates a service registration that shows up in SCM (sc query) and event logs; it’s persistent but not stealthy at the filesystem/stream level. Option D (scheduled task in %APPDATA%) is visible via schtasks/Task Scheduler and leaves clear metadata and execution events. Defenders should enumerate ADS (e.g., streams.exe, Get-Item -Stream *), monitor unusual stream usage, and apply FIM to detect nonstandard streams.

15. While reviewing a mobile app’s crypto, you discover it uses AES-GCM correctly but with a device-scoped random 96-bit nonce that is generated once at first run and reused for all messages on that device. What is the MOST critical risk of this design?
A. None; GCM is secure regardless of nonce reuse as long as the key is strong
B. Only integrity is affected; confidentiality remains intact with reused nonces
C. Catastrophic loss of confidentiality and forgeries if a nonce is ever reused with the same key
D. Slight performance degradation due to repeated GHASH initialization
Correct Answer: C Explanation: AES-GCM is an AEAD mode that is critically dependent on unique nonces per key; reusing a nonce with the same key can reveal plaintext relationships and, more severely, enable computation of the authentication subkey and allow chosen-ciphertext forgeries, making C correct. A is false; GCM security proofs assume nonce uniqueness. B is wrong because both confidentiality and integrity can fail under nonce reuse. D is irrelevant; the issue is not performance. CEHv13 expects candidates to know that AEAD modes (GCM/ChaCha20-Poly1305) mandate unique nonces; developers should use counters or vetted libraries that enforce nonces, or use deterministic constructions that derive nonces safely (e.g., per-message counters, never per-device reuse). Tools like Mobile Security Framework (MobSF) or static analysis can flag constant IV/nonce patterns.

16. During BLE pairing, which pairing method provides the strongest resistance to Man-In-The-Middle (MITM) attacks when a secure external channel is available?
A. Just-Works (no authentication)
B. Numeric Comparison (user verifies a displayed number)
C. Out-of-Band (OOB) pairing using a physically separate secure channel (e.g., NFC)
D. Passkey Entry with a single 4-digit PIN displayed on one device only
Correct Answer: C Explanation: Out-of-Band (OOB) pairing uses an external secure channel (for example NFC, QR scan, or wired exchange) to transfer cryptographic material or confirmation data outside the RF link; because the secret or confirmation is conveyed via a channel an attacker cannot easily manipulate, OOB provides the strongest MITM resistance. Numeric Comparison (B) also provides MITM protection when both devices display the same number and the user verifies it — it is robust for Bluetooth Classic and LE Secure Connections but depends on correct user action. Just-Works (A) provides no MITM protection (it accepts the DH key without authentication), so it is vulnerable. Passkey Entry (D) can be strong when the full passkey is entered by both parties (typically 6 digits) but a single 4-digit PIN displayed on only one device is weaker and easier to social-engineer; overall OOB is the top choice when available.

24. A security policy requires preventing cleartext credential disclosure during sniffing tests. Which application-layer control will MOST effectively mitigate credential theft even if an attacker succeeds at L2/L3 MITM?

B. Block all outbound DNS queries to external resolvers

Correct Answer: A Explanation: Enforcing HTTPS/TLS with valid certificates and HSTS (HTTP Strict Transport Security) (A) prevents easy interception of credentials at the application layer because sensitive flows are encrypted end-to-end; HSTS helps prevent downgrade attacks that might try to force HTTP. 25. A financial services website is configured to support OCSP stapling. Which security improvement does OCSP stapling provide compared to traditional OCSP?

B. It allows the server to provide recent revocation status without contacting the CA in real-time

Correct Answer: B Explanation: OCSP stapling enables the server to “staple” a recent OCSP response signed by the CA into the TLS handshake, avoiding client-CA round-trips and improving both privacy and performance, making B correct. 26. Which of the following is BEST categorized as a volumetric DDoS attack rather than a protocol-state exhaustion or application-layer attack?
A. TCP SYN flood targeting the victim’s backlog queue
B. Slowloris holding many HTTP connections open with partial headers
C. UDP reflection from exposed memcached servers on 11211 with very high amplification
D. TCP RST injection to tear down established connections
Correct Answer: C Explanation: Volumetric attacks aim to saturate bandwidth/packet-processing capacity (measured in bps/pps) and are often achieved via amplification/reflection like memcached UDP (amplification factors that can exceed 10–100× when misconfigured), DNS, NTP, SSDP, or CLDAP. 29. A public-facing legacy web application is confirmed vulnerable to SQL injection, but the vendor patch is delayed for six weeks and the business cannot take the application offline. Which measure is the most appropriate compensating control to mitigate exploitation risk in the interim?
A. Apply emergency OS kernel patches to the web servers within 24 hours
B. Deploy targeted WAF virtual patching rules to block SQLi payloads at the endpoint URI
C. Enforce stricter password history and complexity for all web users
D. Increase full and incremental backup frequency of the database servers
Correct Answer: B Explanation: A compensating control is a security measure that satisfies the intent of a primary control when the primary control (the vendor patch) cannot be implemented in time. DNS tunneling (C) would feature large TXT queries/answers or long subdomain labels carrying data rather than broad random domain churn. Hard-coded IP beacons (D) show stable destinations, not randomized domain lookups. Detection involves linguistic/entropy models, frequency analysis, and sinkholing; prevention includes egress DNS controls and threat-intel DGA seed lists.

116. A defender wants to reduce user impact while neutralizing DHCP starvation attempts launched from infected endpoints on access ports. Which switch configuration is the BEST single change to throttle the attack and preserve normal client access?

B. Trust all access ports to reduce control-plane load on the switch
C. Disable DHCP relay and force all segments to run local servers

Correct Answer: D Explanation: Enabling DHCP snooping with a per-port rate limit on untrusted interfaces throttles the volume of DHCPDISCOVER/REQUEST messages a single attacker can send, preventing scope exhaustion while allowing legitimate clients to function (D). 119. You are hardening credential storage after a breach exposed a database of unsalted SHA-1 password hashes. Which change MOST effectively counters offline cracking and rainbow tables going forward?
A. Enforce 12-character minimums and complexity rules only
B. Encrypt the hash table with AES-256-GCM at rest and keep using SHA-1 for hashing
C. Salt with a single global “pepper” value and keep a fast hash for performance
D. Store passwords using Argon2id/bcrypt/scrypt or PBKDF2-HMAC-SHA-256 with a unique per-user salt and tuned cost (iterations/memory); optionally add an application-level pepper in an HSM
Correct Answer: D Explanation: Rainbow tables exploit unsalted, fast hashes. The proper countermeasure is a unique per-user salt plus a slow (preferably memory-hard) KDF such as Argon2id/bcrypt/scrypt (or PBKDF2 with high iterations), optionally adding a pepper stored separately (e.g., HSM), so D is correct. 120. A Java-based e-commerce site stores a Base64-encoded session cookie that, when decoded, contains a serialized object. Modifying the payload to a known gadget chain results in remote code execution on a vulnerable library version. What web application threat BEST explains this issue?

B. SQL injection via unsafe deserialization of string fields
C. Insecure deserialization leading to arbitrary code execution
D. Server-side template injection (SSTI) via EL expressions in JSP
Correct Answer: C Explanation: Insecure deserialization occurs when untrusted serialized data is accepted and deserialized, allowing attackers to supply gadget chains that trigger dangerous behavior up to RCE; the Base64 cookie containing a serialized object is a hallmark. XXE (A) involves XML parser misconfiguration and external entities, not object streams. SQL injection (B) is about injecting SQL into database queries; while deserialized data may later reach a DB, the described RCE via gadget chains is characteristic of insecure deserialization. SSTI (D) affects template engines (e.g., Freemarker, Thymeleaf, Velocity), whereas the scenario centers on Java object deserialization. 121. During red-team testing you discover that internal hosts are exfiltrating via DNS tunneling. Which set of countermeasures MOST effectively detects and disrupts DNS-based covert channels?

Correct Answer: A Explanation: A is correct because DNS tunneling is best mitigated by layered DNS controls: force internal clients to use controlled resolvers, block external recursive resolvers, limit allowed record types (e.g., TXT), monitor query volume, label length and entropy (base32/base64 indicators), and apply RPZ/Threat Intel to block known malicious zones. 125. Which of the following attacker capabilities made the Kaminsky-style DNS cache poisoning attacks (2008) significantly easier and more reliable against many resolvers at the time?

C. The prevalence of IPv6-only resolvers without fallback

126. While performing a network engagement you craft packets with a forged source IP equal to the gateway’s IP so that target hosts send replies to you. This technique—commonly used to intercept traffic indirectly or to facilitate reflection/amplification attacks—is known as:
A. IP spoofing
B. MAC spoofing
C. DNS spoofing
D. Email spoofing
Correct Answer: A Explanation: IP spoofing (A) is the deliberate falsification of the IP source address field in an IP packet so that the packet appears to originate from another host (e.g., the gateway). This can be used to induce replies to be sent to the spoofed address (useful in reflection/amplification attacks) or, when combined with other techniques, to facilitate interception. MAC spoofing (B) alters the link-layer source (useful for port stealing/ARP tricks) but does not change the IP header. DNS spoofing (C) is about fabricating DNS responses to redirect names to attacker-controlled addresses, not forging IP headers. Email spoofing (D) forges SMTP headers (From:) to impersonate senders; it’s an application-layer spoof, not the network-layer technique described. In CEHv13 terms IP spoofing is an L3 technique that can support sniffing by enabling traffic redirection or by evading source-based filtering.
